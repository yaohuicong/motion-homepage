# 访谈与规划

## 访谈清单

只问还不清楚、而且会改变做法的。用户已经给过的不要再问。

| 要知道的 | 为什么影响做法 |
| --- | --- |
| 主页是谁的、做什么的、给谁看 | 决定文案语气、作品怎么分类、结尾放什么联系方式 |
| 有哪些内容：简介、履历（年份 + 经历）、作品（图、标题、类别、简介、链接）、联系方式 | 决定版块要不要增删；没有履历就去掉 about |
| 角色来源：本人照片 / 已有 IP 形象 / 全新设计 | 决定第一张定稿图怎么出；已有 IP 要保住识别特征 |
| 风格参考：1–2 张喜欢的网站截图或海报 | 决定配色、字体、装饰、角色画法。没有参考时，给 2–3 个方向让用户选，不要自己拍板；参考是别人的作品时只借风格 |
| 手上的工具：能用哪个生图、哪个生视频（是否支持首尾帧） | 决定走视频路线还是纯图片路线 |
| 在哪发布：自己域名 / 免费链接 / 国内访问是否重要 | 决定部署平台和字体加载方式 |

灵感网站（用户没参考时可以推荐）：MotionSites（整页动效）、Pinterest（排版与配色）、React Bits（单个交互组件）、Awwwards（获奖网站）。

## 默认版块

| id | 版块 | 内容 | 角色在做什么（默认） |
| --- | --- | --- | --- |
| hero | 首屏 | 大标题 + 一句介绍 + 按钮 | 正面站在画面右侧，跟着鼠标看 |
| about | 个人履历 | 年份时间线，滚动切换 | 移到左侧，侧身摊手"介绍" |
| folder | 作品目录 | 3D 文件夹，点开出类目卡 | 缩小到右下角，坐着/抱电脑 |
| works | 精选作品 | 横向轮播，点开看详情 | 离场（作品是主角） |
| outro | 结尾 | 大标语 + 联系方式（面板在下半屏） | 从上方掉下来/飞起来，**停在上半屏中间**，周围漂着技能图标 |

版块可以删、可以换顺序；新增版块需要在 `js/sections.js` 的 `RENDER` 里加一个渲染函数。

## 写 plan.md

放在站点目录，作为后面生图和建站的依据。格式：

```markdown
# <名字> 的主页

风格：<参考图要点：底色、强调色、标题字体、整体气质>
角色：<来源；必须保留的特征；本次服装/配饰>
背景底板：<一句话描述，全站共用>

## 版块与角色动线
| 版块 | 文字放哪侧 | 角色姿态（关键图） | 角色位置/大小 |
| --- | --- | --- | --- |
| hero | 左 | 正面站立，双手插兜，好奇表情 | 画面右 2/3 处，半身占画面高 80% |
| about | 右 | 侧身面向右，右手摊开 | 画面左 1/4 处，略小 |
| ...

## 衔接片段
| 衔接 | 首帧 | 尾帧 | 中间的表演 |
| --- | --- | --- | --- |
| hero→about | hero 关键图 | about 关键图 | 转身、走到左边、抬手 |
| ...
```

## 规划时要守住的几条

- **文字和角色各占一边。** 每个版块写清楚文字在哪侧，角色就放另一侧；这决定了姿态关键图的构图。
- **上一段的末帧 = 下一段的首帧。** 衔接片段都从姿态关键图出发和结束，所以只要关键图一致，整站就是一个连续的长镜头。
- **首屏的追视从正面开始、回到正面结束。** 离开首屏时角色会先回到正面，再接 hero→about 的衔接，所以 hero 关键图就是追视的正面那一帧。
- **作品才是主角。** 精选作品版块默认让角色离场或缩到角落，不要抢作品的视觉中心。
