# 部署

网站是纯静态文件（没有构建步骤），任何静态托管都能用。部署前先：

```bash
node <skill>/scripts/check-site.mjs <站点>     # 0 个错误、没有占位素材
```

再删掉不需要发布的文件（`plan.md`、原始视频、`tools/` 可留可删）。

## 选哪个

| 平台 | 适合 | 做法 |
| --- | --- | --- |
| Netlify Drop | 最快，不用装任何东西 | 打开 app.netlify.com/drop，把站点文件夹拖进去，得到 `xxx.netlify.app` 链接；注册后可改名、绑域名 |
| Vercel | 已有 GitHub 仓库 | 导入仓库，Framework 选 Other，直接部署 |
| GitHub Pages | 代码放 GitHub | 仓库 Settings → Pages → 选分支和根目录 |
| Cloudflare Pages | 国内访问相对稳定、带宽大 | Pages → 上传资产（Direct Upload），或连 GitHub |

需要命令行部署时（用户同意后再执行，涉及登录）：

```bash
npx netlify-cli deploy --dir <站点> --prod
npx vercel <站点> --prod
```

## 国内访问

- Google Fonts 在国内可能加载慢：把 `theme.fontsHref` 里的 `fonts.googleapis.com` 换成镜像（如 `fonts.loli.net`），或把字体文件下载到 `assets/fonts/` 自托管。
- 素材总量尽量控制在 30 MB 以内；`frames.py` 用 `--width 960 --quality 72` 可以明显减小体积。

## 以后加作品

作品都在 `site.config.js` 的 `sections.works.items` 里：复制一条，改标题、类别（要和作品目录的 `categories[].key` 对上）、年份、封面路径、简介，再把封面图放进 `assets/works/`，重新部署即可。

如果用户经常更新、又不想碰代码，可以再做一个简单的后台：例如接 Netlify CMS / Decap CMS，把 `works.items` 拆成一个 JSON 文件由后台编辑。这是独立的后续任务，先确认用户确实需要再做。
