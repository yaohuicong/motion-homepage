# 素材：提示词模板与验收

所有素材都是 **16:9 横版**、同一机位、同一张背景。尖括号 `<>` 里按 plan.md 填。提示词用中文（国内模型效果更好），海外模型可直译成英文。

## 0. 通用规则

- 每一张新图都**带上前一步的定稿图作参考**，并在提示词里写明哪些不许变。不带参考、只靠文字描述，角色一定会变脸。
- "不许变"的清单要具体：脸型、五官比例、发型发色、眼镜/配饰、服装、肤色、画风、光线方向、背景、机位、人物大小。只写"保持一致"不够。
- 视频统一：1280×720 或更高、24fps、每段 3–5 秒、**无运镜**（固定机位）、无字幕水印。
- 背景决定拼接是否穿帮：所有视频都上传同一张背景底板，或以姿态关键图为首尾帧（关键图里已经有背景）。

## 画法先定下来

角色画法跟着网站风格走，定下来后写进后面每一条提示词：

| 网站风格 | 角色画法关键词 | 背景底板 |
| --- | --- | --- |
| 深色手绘涂鸦 + 3D 主角（模板默认） | 主角：高品质 3D 动画电影角色渲染，圆润 Q 版，柔和主光 + 一道强调色轮廓光把人物从深色背景里勾出来；贴纸/小角色：2D 粗黑描边涂鸦 | **纯色**，与 `theme.bg` 同色（如 #0d0d12）；色块和涂鸦由网页叠加，会动 |
| 深色手绘涂鸦（全 2D） | 2D 扁平卡通，粗黑描边，赛璐璐上色，夸张表情，色彩饱和 | 同上 |
| 质感 3D | 3D 卡通，黏土/潮玩质感，柔和电影光 | 有纹理的墙面或渐变，全站共用一张 |

| 清新插画 | 水彩/彩铅插画，柔和描边 | 浅色纸纹 |

已有 2D 定稿图时，可以把它当参考图让模型"保持构图、姿态、服装不变，重新做成 3D 渲染"，构图和人物位置基本能保住。3D 主角配 2D 涂鸦贴纸是常见的混搭，反差反而更跳。

纯色背景最省心：视频边缘和网页完全融为一体，手机竖屏渐隐也看不出接缝；AI 视频在纯色上也最不容易"背景闪"。

## 1. 角色定稿图

**本人照片 → 3D 卡通：**

```
把参考照片里的人变成 3D 卡通角色，<黏土/皮克斯/潮玩> 质感。保留本人的发型、脸型特征、眼镜和标志性服装<具体写>。
表情夸张生动（<好奇睁大眼 / 咧嘴笑>），<半身/全身>，正面站立，双手<自然下垂/插兜>，看向镜头。
柔和电影感打光，背景<纯色/简单渐变>，16:9 横图，人物位于画面右侧三分之二处，头顶留出空间。
```

**已有 IP → 换装定稿：**

```
参考图中的角色，保持角色识别特征完全不变：<例：白色蓬松卷发、头顶一根带小圆球的天线、黑色粗框圆眼镜、圆脸大眼>。
本次换装为 <契合主题的服装与配饰，例：紫色连帽卫衣、荧光黄绿抽绳、胸前小徽章>。
<画法关键词，例：2D 扁平卡通，粗黑描边，赛璐璐上色，色彩饱和>，表情<…>，正面半身，看向镜头，
纯色背景 <#0d0d12>，16:9 横图，人物在画面右侧三分之二处，头顶留出空间。
```

**验收**：脸和识别特征一眼能认出；服装细节清楚；头顶和两侧留了空间（后面转头不出画）。让用户确认后，这张图就是"定稿图"，后面每一步都带它。

## 2. 背景底板

手绘涂鸦风格直接用纯色（用 `ffmpeg -f lavfi -i color=c=0x0d0d12:s=1920x1080 -frames:v 1 bg.png` 生成），不必生图。质感风格才需要：

```
<一句话场景，例：深色工作室墙面，微微做旧的墨绿色水泥质感，右侧有柔和的紫色光晕>，没有任何人物和文字，
16:9，与参考图同样的机位、焦段和光线方向，画面中央和左侧干净，适合放文字。
```

**验收**：没有人；左侧/中部足够干净能压文字；颜色与参考风格一致。顺手取它的四角颜色作为网页底色（`frames.py` 会报）。

## 3. 姿态关键图（每个版块一张）

参考图：定稿图 + 背景底板。

```
参考图 1 的角色，放进参考图 2 的背景里，机位、光线和背景完全不变，角色外观（脸、发型、配饰、服装、画风）完全不变。
姿态：<plan.md 里该版块的姿态，例：侧身面向画面右侧，右手向右摊开像在介绍>。
位置与大小：<例：位于画面左侧四分之一处，半身，头部高度约占画面 30%>。表情：<…>。16:9。
```

**验收**：把所有关键图排成一行看——同一个人、同一个背景、同一光线。位置和大小符合 plan（文字那侧是空的）。hero 关键图就是追视的正面帧。

## 4. 追视闭环（首屏）

目标：一段视频从正面开始，头和眼睛依次看向 **左、左上、上、右上、右、右下、下、左下，再回到左**，最后回到正面。顺序固定，配置和工具都按这个顺序。

为什么左下之后要再回到左：这样 8 个方向首尾相接成一整圈，任意两个相邻方向之间都有真实的转头帧。如果左下直接回正面，"左下↔左"之间就没有画面，鼠标经过那里会卡顿或跳帧。

### 路线 A：分段首尾帧（能传首帧+尾帧；最可控，但要多出 8 张方向图、10 段视频）

先出 8 张方向图（参考图：hero 关键图）：

```
参考图中的角色，只改变头部朝向和眼神：头部 <向左转约 30° / 向左上抬头约 20° 并左转 20° / 抬头约 20° / …>，眼睛看向同一方向。
除头部角度和眼神外，脸型、五官、发型、配饰、服装、身体姿势、画面位置、人物大小、光线、背景全部不变。16:9。
```

再用支持首尾帧的视频模型生成 10 段（正面→左、左→左上、…、右下→下、下→左下、左下→左、左→正面），每段约 1 秒：

```
固定机位，角色身体不动，只有头部和眼睛从首帧的朝向平滑转到尾帧的朝向，动作自然、匀速，结束时停稳。
肩膀不晃动，背景、光线、人物位置和大小全程不变，不眨眼，不说话。
```

拼接：`python3 frames.py gaze-join assets/clips/gaze 段1.mp4 … 段10.mp4`，keys 自动生成。

### 路线 B：一条视频 + 标定（能传首帧+尾帧；最省事，首尾都传 hero 关键图，但需要手动标定）

视频模型首帧和尾帧都用 hero 关键图，时长 8–10 秒：

```
固定机位。角色身体保持不动，头部和眼睛依次缓慢看向：左、左上、上、右上、右、右下、下、左下、再转回左，每个方向停留约半秒，
最后转回正面看向镜头，最后一帧与第一帧完全一致。肩膀不晃动，背景、光线、人物位置与大小全程不变。
```

用 `frames.py extract` 拆帧，再用 `tools/calibrate.html` 标出每个方向落在第几帧。

### 路线 C：只能生图，没有视频工具

一共 9 张图：hero 关键图（正面）+ 8 张方向图（提示词同路线 A 的方向图）。

```bash
python3 frames.py images assets/clips/gaze 正面.png 左.png 左上.png 上.png 右上.png 右.png 右下.png 下.png 左下.png
```

配置（`head` 换成你的角色头部在画面中的位置，可以用 `tools/calibrate.html` 点一下得到）：

```js
gaze: { src: 'assets/clips/gaze/{n}.webp', count: 9, loop: false, maxWalk: 0,
  keys: [{f:0,x:0,y:0},{f:1,x:-1,y:0},{f:2,x:-0.7,y:-0.7},{f:3,x:0,y:-1},{f:4,x:0.7,y:-0.7},{f:5,x:1,y:0},{f:6,x:0.7,y:0.7},{f:7,x:0,y:1},{f:8,x:-0.7,y:0.7}],
  head: { x: 0.66, y: 0.42 }, radius: 0.3, deadzone: 0.16 },
```

衔接也用图片：每段只需要"上一版块姿态图 + 下一版块姿态图"两张，滚动时两张交叉溶解：

```bash
python3 frames.py images assets/clips/t1 hero姿态.png about姿态.png
```

```js
{ from: 'hero', to: 'about', src: 'assets/clips/t1/{n}.webp', count: 2, blend: true },
```

方向之间、版块之间都是溶解切换，没有转头和走动的过程。交付时如实告诉用户：有视频工具后可以升级成真正的动作。

### 追视验收

- 8 个方向都有，左下之后回到了左（闭成一圈），且每个方向能看出明显区别（不是只动眼珠）。
- 回到正面的那一帧和第一帧几乎一样（否则闭环处会跳）。
- 全程肩膀、身体、背景不动；脸不变形；不眨眼不张嘴（这些在鼠标反复拖动时会显得抽搐）。

### 路线 D：只能传首帧的视频工具（推荐）——星形 8 条短视频

一条长视频里连做 8 个方向 + 表情，模型越往后越"跑偏"（实测：第 2 秒起眼镜消失、身体整个转过去、最后回不到正面）。改成 **8 条都从同一张首屏关键帧出发**的短视频，每条只转向一个方向并做一个表情，然后保持不动：

```
图生视频，首帧是参考图。固定机位，镜头完全不动。
角色全程戴着<关键识别物，如黑色粗框眼镜>，不能消失、不能变形；<发型、配饰>全程保持原样。
身体、肩膀完全不动，位置和大小不变，只有头部和眼睛转动；纯色背景全程不变。
动作：第 0–1.5 秒，从首帧的正面平滑地<头转向画面左侧，眼睛也看向画面左侧>，转动幅度约 20 度，同时表情变成<斜眼撇嘴>；
第 1.5 秒以后保持这个朝向和表情完全不动，直到结束。不要眨眼，不要出现文字。5 秒，16:9 横屏。
```

8 个方向：画面左 / 左上 / 上 / 右上 / 右 / 右下 / 下 / 左下（写"画面左侧"，不要写"他的左边"，模型会搞反）。每个方向配一个夸张表情（撇嘴、吐舌、惊讶、坏笑、鼓腮、龇牙、害羞、委屈），很出效果。

```bash
python3 scripts/frames.py gaze-star assets/clips/gaze L=左.mp4 UL=左上.mp4 U=上.mp4 UR=右上.mp4 R=右.mp4 DR=右下.mp4 D=下.mp4 DL=左下.mp4 --turn 1.6 --fps 20
```

脚本只取每条前 1.6 秒（转头过程），回正时倒放复用同一批帧，并打印带 `map` 的 gaze 配置。网页里鼠标从一个方向换到另一个方向时，角色先回正面、再转向新方向——所有方向都在同一张正面帧处衔接，不会跳。

## 只能传首帧的视频工具：链式生成

有些视频工具（包括只接受"一张参考图作首帧"的图生视频接口）不能指定尾帧。这时按顺序一段接一段生成，用上一段的**真实最后一帧**做下一段的首帧：

1. 追视用上面的**路线 D（星形 8 条短视频）**，都以 hero 关键图做首帧，互不依赖，可以同时提交。
2. 用 hero 关键图做首帧，生成 hero→about 衔接；提示词写清楚结束时的姿态、位置、大小。
3. 取这段视频的最后一帧（`ffmpeg -sseof -0.1 -i t1.mp4 -frames:v 1 t1_last.png`）做首帧，生成 about→folder；依此类推。

这样每段的首帧一定等于上一段的尾帧，衔接零跳变；代价是后一段要等前一段生成完，而且某一段重生成后，它后面的段都要重做。每段生成完先检查尾帧姿态和位置，不对就重生成这一段，再继续往下。

## 5. 衔接片段

### 只能传首帧时的实测经验（天线小子主页，4 段全部做通）

- **按顺序链式生成**：t1 首帧 = 追视的正面帧；之后每段首帧 = 上一段最后一帧（`ffmpeg -sseof -0.05 -i 上一段.mp4 -frames:v 1 下一段_首帧.png`）。
- **每段提示词前面都加同一段"通用约束"**：固定机位、不推拉；背景始终是首帧的纯深色、不要光晕/地面/阴影；关键识别物（眼镜、发型、天线、衣服配饰）保持原样。
- **结尾写清楚"从第 4 秒起保持不动"**，下一段才好接。
- **动作越简单越稳**：t3 第一版写"站起来挥手再躲下去"，模型中途切了个近景、人变大；改成"坐着挥手，再整个人垂直往下沉"就一次通过。
- **截短比重做省事**：t3 最后人完全沉出画面（下一段就没有角色可以接了），直接截到"只露头顶"的那一帧（`select=lte(n\,102)`），用这一帧当 t4 首帧。
- **首帧看不到脸时用"倒放法"**：t4 第一版的首帧只露出头顶，模型看不到脸，结尾"猜"出了一张别人的脸（棕眼睛、脸变长）。改法：先用生图工具出结尾姿势的定稿图（参考图用主角定稿，保证脸对），用它做首帧，生成"反方向"的动作（欢呼 → 缩成一团沉到画面下边），再把视频倒过来播放。倒放后的开头和上一段结尾位置略有差别时：纯色背景下把开头几十帧整体水平平移、慢慢移回原位，看不出来；高度差就换上一段的截断帧来对齐（不要上下平移，会露出身体被画面切断的边）。
- **每段生成后先查**：抽帧看动作；再逐帧算人物的中心位置和宽度，突然跳变 = 模型偷偷切了镜头，要重做。
- 版块和人物位置对照（模板默认五段）：首屏人物在右 → 关于我走到左边 → 作品目录回到右边坐下 → 精选作品躲到底部只露头 → 结尾跳到上方正中。人物和文字永远各占一边。

### 通用写法


参考：首帧 = 前一个版块的关键图，尾帧 = 后一个版块的关键图，时长 3–5 秒。

```
固定机位，背景与光线全程不变。角色从首帧的姿态与位置，<plan.md 里的表演，例：转身面向右侧，轻快地走到画面左侧，停下后抬起右手摊开>，
最终与尾帧的姿态、位置、大小完全一致并停稳。动作连贯自然，角色外观全程不变，不出现其他人物、文字或道具。
```

离场/入场用"走出画面右侧""从画面上方掉进来"这样的描述；离场的尾帧可以用空背景底板。

**验收**：首帧和尾帧分别与两张关键图一致（叠在一起看，位置不跳）；中间角色不变脸、衣服不变样；背景纹理和光影不闪；没有多余的手或道具。

## 6. 作品封面

用户已有作品图时直接用，统一裁成 16:10（`ffmpeg -i in.png -vf "crop=iw:iw*10/16" out.webp` 或在设计软件里裁）。没有时，每类作品出一张封面：

```
<作品类型> 作品展示图，<作品内容>，<与主页统一的色调>，干净的展示背景，16:10，高质量商业摄影风格。
```

## 7. 卡片插图、小卡通角色、手绘配饰

手绘涂鸦风的页面靠这些"小东西"撑起热闹感，和主角用同一种画法：

- **作品/类目卡片插图**：每张卡一张插图（16:10），题材对应作品内容；可以让主角客串，画法、配色和主角一致。
- **小卡通角色**（吉祥物、小怪兽、表情贴纸）：画在**纯品红 #FF00FF 背景**上（别用深色底：深色衣服和描边会被一起抠掉），再用 `python3 scripts/cutout.py 输入.png 输出.webp` 抠成透明底，配置成 `decor` 里的 `{ type: 'img', src, x, y, size }`，会轻轻上下浮动。
- **手绘配饰**（耳机、马克笔、速写本、场记板一类和主角人设相关的道具）：同样品红背景出图、抠图，当贴纸散落在版块角落。

```
<画法关键词>，一个 <小角色/道具描述> 的贴纸插画，粗黑描边，色彩 <强调色>，单独一个物体居中，
纯品红色背景 #FF00FF，四周留空，不要文字，不要阴影。
```

省事的做法是一次出一张"贴纸合集"：提示词里列出 4–8 个物体，写明"每枚之间留出大段空白、互不接触、互不重叠"，外轮廓加一圈白色贴纸边。出图后一条命令拆开：

```bash
python3 scripts/cutout.py 合集.png assets/stickers --split     # → 01.webp 02.webp …（从左到右、从上到下）
```

脚本会把边缘混进来的品红减掉，贴到深色页面上不会有粉边。拆出来的数量比预期多（碎颜料点被单独拆出）就调大 `--min-area`；两枚连在一起拆不开，就重新出图并强调间距。

参考图是别人的作品时，这些插图和小角色都要自己重新设计，只学它"有很多小插图和小角色"这个做法。

## 出了问题怎么描述

把生成失败的视频交回给模型（或自己抽帧看），说清楚具体现象，而不是"不够自然""丝滑一点"：

| 模糊的说法 | 具体的说法 |
| --- | --- |
| 不自然 | 第 2.5 秒人物整体向右平移了大约 5% 画面宽度 |
| 眼神怪 | 眼睛比头提前转向，头还没动眼珠已经到了右边 |
| 动作太大 | 抬头超过 30°，下巴露出太多，脸被压扁 |
| 衔接不上 | 最后一帧右手还在胸前，关键图里右手是摊开的 |
| 背景在闪 | 背景墙的纹理每秒都在变，左上角光斑忽明忽暗 |

在新提示词里把这些写成约束（例："全程人物水平位置不变""眼睛与头部同步转动""抬头不超过 20°"）。
